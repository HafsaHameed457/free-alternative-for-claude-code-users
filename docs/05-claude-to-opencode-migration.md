# 05-claude-to-opencode-migration.md\n\nFor developers transitioning from Claude Code to OpenCode, this section provides a bridge, highlighting key differences, mapping common actions, and offering tips for a smooth migration.\n\n## Key Differences between Claude Code and OpenCode\n\nWhile both Claude Code and OpenCode are AI-powered coding assistants, their interaction models and underlying mechanisms differ significantly:\n\n| Feature              | Claude Code (Typical Interaction)           | OpenCode (Typical Interaction)                                                              |\n| :------------------- | :------------------------------------------ | :------------------------------------------------------------------------------------------ |\n| **Interaction Model**  | Conversational, natural language directives | Tool-based, explicit calls to specialized tools                                           |\n| **Environment Access** | Simulated/abstracted code editing           | Direct CLI interaction, real file system access, live command execution                     |\
| **Determinism**        | More interpretive, can be less predictable  | More deterministic due to explicit tool calls, actions are verifiable                       |\
| **Transparency**       | Less insight into internal reasoning        | Clear output of tool calls (e.g., `read`, `bash`), showing exactly what\'s being done        |\
| **Error Handling**     | Often high-level explanations             | Detailed error messages from underlying tools (e.g., `bash` command failures, `edit` errors) |\
| **Pathing**            | Often implicit or relative                  | Requires explicit absolute paths for file system operations                                |\
\n\n## Direct Equivalents and Mapping\n\nHere\'s how common actions you might perform with Claude Code translate to OpenCode\'s tool-based approach:\n\n| Claude Code Action/Prompt                                | OpenCode Equivalent Tools/Workflow                                                                                                      |\
| :------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------- |\
| \"Show me the contents of `src/App.js`\"                   | `opencode read --filePath /path/to/your/project/src/App.js`                                                                               |\
| \"Find all `.css` files in the project\"                   | `opencode glob --pattern \"**/*.css\"`                                                                                                      |\
| \"Change `oldVar` to `newVar` in `util.js`\"             | `opencode edit --filePath /path/to/your/project/src/util.js --oldString \"oldVar\" --newString \"newVar\" --replaceAll true`                  |\
| \"Run `npm install`\"                                      | `opencode bash --command \"npm install\" --description \"Install project dependencies\"`                                                  |\
| \"Create a new file `components/Button.js` with ...\"     | `opencode write --filePath /path/to/your/project/src/components/Button.js --content \"// Button component code\"`                         |\
| \"What are the API endpoints in `server.py`?\"             | `opencode read --filePath /path/to/your/project/server.py` followed by `opencode grep --pattern \"@app.route\" --include \"server.py\"` |\
| \"Fix this bug in `index.js`\" (complex, multi-step)       | `opencode task --subagent_type \"general\" --prompt \"Fix bug in index.js. First, identify the root cause, then implement a fix and verify with tests.\"` |\
| \"Should I use React or Vue for the frontend?\"            | `opencode question --questions \"Which frontend framework do you prefer?\" --options \"React (Recommended)\", \"Vue\"`                          |\
\n\n## Workflow Adjustments for a Smooth Transition\n\nTo effectively switch from Claude Code to OpenCode, consider these adjustments to your workflow:\n\n1.  **Think in Terms of Tools:** Instead of high-level directives, start thinking about which specific OpenCode tool is needed for each part of your task. If you want to read, use `read`. If you want to run a command, use `bash`.\n\n2.  **Be Explicit with Paths:** Always provide absolute paths for file operations. If you\'re unsure of a path, use `glob` to find it first.\n\n3.  **Leverage `grep` and `glob` for Discovery:** Before asking OpenCode to make changes, use `grep` and `glob` to help it (and yourself) understand the scope and context of the modifications.\n\n4.  **Embrace `bash` for Control:** The `bash` tool is your direct link to the underlying operating system. Use it for anything that involves running external programs, Git commands, build tools, or tests.\n\n5.  **Utilize `question` for Decision-Making:** If a task has multiple valid approaches or requires a preference, use `opencode question` to allow OpenCode to ask for your input. This maintains your control over the development process.\n\n6.  **Delegate with `task` for Complexity:** For broad, multi-step tasks (like \"Implement a new feature\"), don\'t try to break down every single step yourself. Use the `opencode task` tool to launch a sub-agent that can handle the complexity autonomously, but remember to specify exactly what information the agent should return back to you.\n\n7.  **Review Tool Outputs:** Always pay attention to the output of OpenCode\'s tool calls. This is your primary way to understand what it\'s doing, verify its actions, and debug any issues.\n\nBy adopting these habits, you\'ll find OpenCode to be a powerful, transparent, and precise partner in your software development journey.\n
